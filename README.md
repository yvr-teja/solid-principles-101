# SOLID Principles in Java

## Overview

This repository is dedicated to learning and implementing the **SOLID principles** in Java.

SOLID is a set of five fundamental object-oriented design principles that help developers write clean, maintainable, scalable, reusable, and loosely coupled code.

The goal of this repository is to understand each principle through simple explanations, practical Java examples, and real-world use cases.

## SOLID Principles

| Principle | Full Form | Description |
|---|---|---|
| **S** – SRP | Single Responsibility Principle | A class should have only one reason to change. |
| **O** – OCP | Open/Closed Principle | Software entities should be open for extension but closed for modification. |
| **L** – LSP | Liskov Substitution Principle | Subtypes should be replaceable for their base types without affecting program correctness. |
| **I** – ISP | Interface Segregation Principle | Clients should not be forced to depend on methods they do not use. |
| **D** – DIP | Dependency Inversion Principle | High-level modules should depend on abstractions, not low-level implementations. |

## Learning Objectives

- Understand the fundamentals of SOLID principles.
- Learn how to apply SOLID principles in Java.
- Identify common design problems and code smells.
- Understand tightly coupled vs loosely coupled code.
- Practice interface-based and abstraction-driven design.
- Improve code reusability, maintainability, and testability.
- Apply SOLID principles to real-world application scenarios.
